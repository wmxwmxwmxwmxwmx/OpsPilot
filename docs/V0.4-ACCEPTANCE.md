## 2. 完整架构

```mermaid
flowchart TD
  Client[HTTP / SSE Client] --> HTTP[FastAPI + safe HTTP span]
  HTTP --> WS[WorkflowService / execution span]
  WS --> LOCK[PG advisory lock]
  LOCK --> GRAPH[Existing LangGraph]
  GRAPH --> RAG[retrieve_runbook node]
  RAG --> EMB[EmbeddingProvider: Fake or configured API]
  EMB --> PGV[RunbookRepository: pgvector exact search]
  DOC[Versioned Markdown Runbooks] --> IMPORT[Loader / Splitter / Import CLI]
  IMPORT --> EMB
  PGV --> PLAN[plan / LLM generation]
  PLAN --> REG[ToolRegistry / validation]
  REG --> LOCAL[Existing local tools]
  REG --> APPROVAL[Existing HITL / mock idempotent action]
  REG --> ADAPTER[MCPTool adapter]
  ADAPTER --> MCPCLIENT[MCPClient: v2 Streamable HTTP]
  MCPCLIENT --> SERVER[Loopback MCP mock server]
  LOCAL --> PLAN
  APPROVAL --> PLAN
  SERVER --> PLAN
  PLAN --> FINAL[finalize / retrieved citations]
  FINAL --> SESSION[Redis Session + receipt]
  SESSION --> INCIDENT[Incident + workflow completed transaction]
  INCIDENT --> Client
  GRAPH -. persistent node boundary .-> CP[AsyncPostgresSaver]
  HTTP -. metrics .-> MET[/metrics]
  WS -. metrics .-> MET
  MET --> PROM[Prometheus scrape + storage]
  PROM --> GRAFANA[Provisioned Grafana dashboard]
  HTTP -. OTLP .-> TEMPO[Tempo trace storage]
  SERVER -. propagated W3C trace / OTLP .-> TEMPO
  TEMPO --> GRAFANA
  INCIDENT -. safe historical summaries .-> CACHE[Existing Redis Cache-Aside]
```

## 4. 一次 Redis 请求的实际调用链

1. `app/api/workflows.py:create()` 接收 `POST /api/v1/workflows`；先用本地 token 授权，再调用
   `WorkflowService.create()` 创建持久初始状态，JSON 调用 `run()`，SSE 调用 `stream_events()`。
2. `app/workflow/service.py:WorkflowService.stream()` 用 `execution_events()` 创建单次执行 Span/指标边界，
   `_stream()` 获取原数据库锁、读取 Checkpoint，按 action 选择初始状态、`None` resume 或 Command approval。
3. `app/workflow/graph.py:build_graph()` 的 START → `retrieve_runbook` → 原 `plan`。
   `WorkflowNodes.retrieve_runbook()` 在匹配运维查询时调用 `Retriever.retrieve()`。
4. `app/knowledge/retriever.py:Retriever.retrieve()` 嵌入当前 Query；
   `app/knowledge/repository.py:RunbookRepository.search()` 用模型/维度过滤和 pgvector 余弦距离查询 Top-K。
   State 仅保存当前有限内容与来源。`operation` 在 Embedding、vector、rag 边界结束后记录耗时/结果。
5. `WorkflowNodes.plan()` 把知识放入低信任 user 数据消息，调用 `BaseLLM.generate()`。
   本次 `WorkflowMockLLM.generate()` 选择 `mcp_get_mock_redis_metrics`；真实模式用原 OpenAICompatibleLLM。
6. 原 `validate_tool()` 验证受控工具、参数和安全分类，`execute_tool()` 调
   `app/mcp/adapter.py:MCPTool.execute()`；再由 `MCPClient.call()` 使用官方 v2 Client 发起远端调用。
7. `app/mcp/server.py:create_server()` 注册的 `get_mock_redis_metrics()` 真正返回模拟 `hit_rate=0.42`。
   Adapter 删除未审阅结果字段，原 observation/ToolResult 语义不变。远端工具不连接真实 Redis。
8. 再次 `plan()` 生成基于模拟证据的排查建议；`finalize()` 经
   `app/knowledge/citations.py:render_references()` 从真实检索结果生成路径、版本、章节和 Chunk ID 引用。
9. `WorkflowService._stream()` 复用 `commit_session()` 的 Redis 回执和乐观并发控制，再调用
   `app/workflow/repository.py:WorkflowRepository.complete()`，在 PostgreSQL 事务中写 Incident 和完成状态。
   `app/incident/schemas.py` 的受控摘要目录包含 MCP 工具名称；不会存原始 ToolResult。
10. 只有提交成功才向 SSE 发 `final` 和 `workflow_completed`。HTTP 与业务终态分别统计；审批等待不计完成。
11. `app/observability/http.py:ObservabilityMiddleware.__call__()` 创建并结束 HTTP Span、设置 X-Trace-ID，
    用真实路由模板计数。`Telemetry.operation()` 记录受控子操作；`execution_events()` 每次推进生成器时
    attach、yield 前 detach、finally end。OTLP 在 BatchSpanProcessor 的有界队列中异步导出。
12. `MCPClient.connection()` 注入 W3C HTTP header，SDK 请求 meta 也传递 W3C 上下文；MCP 服务提取上下文，
    Remote Tool 在同 Trace 中成为 client call 后代。Grafana 经 provisioned Tempo datasource 查询层级。

## 6. 可复现演示

完整命令见 README 的 V0.4 章节，按以下顺序：

1. 使用 Conda Python 3.11 安装 `pip install -e '.[dev]'`。
2. 显式配置本地测试数据库及 V0.3 token/checkpoint；管理员在获授权数据库启用 vector，执行
   `alembic upgrade head` 和 `python -m app.cli.checkpoints setup`。
3. 启用 RAG，指定 Fake（链路演示）或真实 API（语义验证），执行 `python -m app.cli.runbooks`。
4. 独立启动 `python -m app.mcp.server`；MCP 进程 tracing 服务名设 `opspilot-mcp`。
5. 启用 Workflow/RAG/MCP/Metrics/Tracing，运行 OpsPilot，设置完整 OTLP HTTP endpoint。
6. 启动监控 Compose 或按 README 使用官方原生二进制；检查真实网络和 allowlist。
7. 发起 Redis 问题到 `/api/v1/workflows?stream=true`，确认 `workflow_completed` 与引用。
8. 访问 `/metrics`、Prometheus Targets、Grafana Dashboard；从 X-Trace-ID 到 Tempo Explore 查看调用链。
9. `python -m app.cli.observability_check` 自动验证上述链路；可用四个 URL 参数指定本次
   18000/19090/13000/13200 端口，OTLP 为 14318。
10. 受控故障：以 `--fail-redis` 重启模拟 MCP，发起一次 Workflow；正常重启 MCP 后 resume 原任务，
    比较错误/恢复 Counter 与新旧 Trace ID。

所有数据库、服务端口、OTLP 地址和监控 IP 必须与实际环境一致；不要复制示例账号当生产凭据。

## 7. 当前技术债与边界

| 主题 | 当前策略与剩余工作 |
|---|---|
| Embedding 质量/成本 | Fake 无语义保证；真实 Provider 已实现但未配置验证。需真实多语言标注集、阈值校准、批量限流和费用控制 |
| 知识版本 | Git 文档 + 文档级索引替换；无全库原子发布、删除同步、权限过滤或历史版本召回 |
| MCP 信任 | 本机固定目录、拒绝未知 Schema/描述/URL；无远端 OAuth/RBAC/生产证书和通用写工具 |
| Prompt Injection | 数据角色隔离、引用验证、最小工具能力；不能保证自由文本模型不被误导，也不是完整 DLP |
| Label cardinality | 受控 operation/route，拒绝 ID 标签；新增工具和路由仍需审阅标签增长 |
| Sampling/成本 | 配置 ParentBased + ratio、批量有界队列；未做真实流量容量测试，低采样可能漏故障，出口故障允许丢 Span |
| Trace 保留 | Tempo 示例 24h 本地存储；生产需要对象存储、访问审计、清理、备份及合规策略 |
| Resume 关联 | 每次执行新 Span/Trace，以 workflow.id/thread.id 关联；无 Span Links/持久查询索引 |
| 多进程 Metrics | 当前只验收单 worker，需 multiprocess 启动环境、live Gauge 和 worker 清理，或逐 worker scrape |
| 生产认证隔离 | Workflow 仍是本地共享 token；监控 IP/token 是开发保护，不是用户/租户授权。无生产自动修复能力 |
| 运维部署 | Compose 文件已提供，WSL Docker 网络未实测；本次真实验收为原生进程，二者区别明确记录 |
| 测试资源保留 | 为满足不删除数据库要求，每项测试保留独立库，会占空间；后续应由操作者选择整个一次性集群的保留策略 |
